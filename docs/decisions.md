# Decision log

Approved decisions go here together with the contract change that implements them (README §6).
Status: **Approved**, **Proposed** (awaiting team approval), **Open** (unresolved).

| ID | Decision | Status | Implemented in |
| --- | --- | --- | --- |
| D-001 | **Trip capacity.** Mock demo uses 4 occupants including the Booker (`TRIP_CAPACITY=4`). Live mode refuses to start without an explicit value. Each trip stores its capacity at creation. Tests run at 4 and 6. | Open (live value) | `src/config/env.ts`, `TripService.createTrip` |
| D-002 | **Trips at least an hour apart.** A student can be confirmed in several upcoming, non-cancelled trips, but no two may depart within 60 minutes of each other (`TRIP_GAP_MINUTES`). The linked return leg of a trip is never counted against it. New error `409 ACTIVE_TRIP_EXISTS` on join and create. | Proposed (requested by product owner, 2026-11-14) | `TripService.tooClose` |
| D-003 | **Leave cutoff.** Riders can leave until `LEAVE_CUTOFF_MINUTES` (default 60) before departure; after that, `409 LEAVE_WINDOW_CLOSED` and the UI points them to party chat. The cancellation fee stays agreement text only; nothing is charged. | Proposed (requested by product owner, 2026-11-14) | `TripService.leaveTrip`, `LeavePanel` |
| D-004 | **Region rule.** 24 hand-drawn LA regions (`src/lib/regions/regions.ts`). A location's region is strict polygon containment. Trips can only be created to destinations inside a region; discovery warns when a searched place is outside every region. | Proposed (boundaries need approval) | `LocationService`, `TripService.createTrip`, `DiscoverScreen` |
| D-005 | **Party signup and overflow.** MVP join is single-rider only. A full trip returns `409 TRIP_FULL` and the UI offers a prefilled “Create a similar trip”. The earlier prototype's party-size signup and automatic overflow listing are removed until the allocation and consent rules are approved. | Proposed (per README §4) | `JoinPanel` |
| D-006 | **Region-center drop-off.** The HTML prototype modelled trips as going to a region, with each rider's own destination and a drop-off at the region center. The contract models a trip with one `destinationLocationId`. Per-rider destinations are now added by D-010; the region-center drop-off point itself is still open. | Partly resolved by D-010 | `prototype/` (reference only) |
| D-007 | **Rider-joined notifications.** The trip-posted banner tells the Booker they'll be notified when riders join. No delivery channel exists yet (email, push or SMS). | Open | `TripDetailScreen` |
| D-008 | **Creator is the Booker.** The trip creator is automatically the Booker; there is no opt-in or opt-out on the create form. The create UI states the Booker role rather than offering it as a choice, and the service records the active agreement version and time on the Booker's membership. `POST /api/trips` does not take agreement fields. | Proposed (updated 2026-11-14 per product owner) | `CreateTripScreen`, `TripService.createTrip` |
| D-010 | **Car-train routing with a detour limit.** Every rider has their own drop-off (`trip_participants.destination_location_id`; the creator's is the trip destination). No stop is fixed as the last: the planner tries every order and keeps the shortest drive in which EVERY rider's planned ride is within `ROUTE_MAX_DETOUR_MINUTES` (default 10) of their own direct ride, so whoever ends up last is the final destination (normally the farthest rider). Max 4 riders per trip (`TRIP_CAPACITY`, so up to 3 stops before the final one), 1 min pull-over per extra stop. A joiner is admitted only if everyone already aboard stays inside the limit; riders aboard are never dropped. Joining takes an optional `destinationLocationId` (defaults to the trip's) and can fail with `409 ROUTE_DETOUR_EXCEEDED`; `GET /api/trips/:id/fit` previews the result; destination search returns only trips the stop fits (`TripView.fit`). Drive times: Google Routes, traffic-aware at the departure time, when `GOOGLE_MAPS_API_KEY` is set (falls back to a distance and time-of-day estimate if Google is unreachable); otherwise the estimate. Times are taken once at departure, so a long ride is approximated as if it ran in departure-time traffic. Region rule (D-004) still applies to each rider's stop; on a return leg stops are campus drop-offs. Fares are out of scope (handled elsewhere). | Proposed (limit and stop cap need approval) | `src/lib/routing/`, `TripService.joinTrip/fitTrip/searchTrips`, `tests/routing.test.ts`, `tests/trip-routes.test.ts` |
| D-011 | **Fare split.** Ported from the team's Python `calculate_settlement` (`src/lib/pricing/settlement.ts`, exact BigInt fractions, verified against the original on shared cases). Each stretch of the route is paid by the riders aboard it, split evenly; stop fees and empty stretches are spread by distance; whole cents add up exactly; a real Uber total, when known, replaces the estimate. Route miles come from Google Routes (same request as drive time) or a distance estimate. Rates are demo defaults (`UBER_PRICE_PER_MILE=2.50`, `UBER_STOP_FEE=1.00`): set the real values. The UI shows each rider's estimated share and the solo price, and flags an option that is cheaper than the fastest one. **Booker:** the Python picks the rider with the longest trip as Booker; the app instead passes the trip creator (D-008) so reimbursements go to them. Nothing is charged; no real-Uber-total input exists yet. | Proposed (rates, stop fee and Booker rule need approval) | `src/lib/pricing/`, `TripService.pricingFor`, `tests/settlement.test.ts` |
| D-009 | **No-show reporting.** Only the Booker can file a report, only after departure, one per rider per trip. Reports stay `pending` and never change membership or issue strikes. Can be switched off with `ATTENDANCE_REPORTING=off`. | Proposed (policy open) | `AttendanceService` |
